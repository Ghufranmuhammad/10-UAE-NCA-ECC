# Third-Party & Cloud Security Summary

## Introduction

Organizations increasingly depend on vendors, suppliers, SaaS platforms, cloud providers, and managed service providers. A security weakness at a third party can create cybersecurity, privacy, compliance, financial, and operational risks for the organization.

Third-party and cloud security therefore requires organizations to assess suppliers before onboarding them, establish security requirements through contracts, monitor their security posture, and securely terminate relationships when services are no longer required.

---

## 1. Third-Party Cybersecurity Risk

### Purpose
Identify and manage cybersecurity risks introduced by suppliers and service providers.

### Business Value
Reduces the possibility that a supplier compromise will affect DesertTech's systems, data, or operations.

### DesertTech Example
DesertTech evaluates the cybersecurity posture of vendors that process confidential customer information.

### Audit Evidence
- Third-party risk register
- Vendor assessments
- Risk assessment reports
- Vendor security reviews

---

## 2. Vendor Due Diligence

### Purpose
Evaluate a vendor's security capabilities before entering into a business relationship.

### Business Value
Helps DesertTech identify security weaknesses before granting a supplier access to systems or information.

### DesertTech Example
Before onboarding a cloud provider, DesertTech reviews its security certifications, MFA controls, encryption, incident response capabilities, and disaster recovery arrangements.

### Audit Evidence
- Completed vendor questionnaire
- Security certifications
- Due diligence checklist
- Assessment report

---

## 3. Security Requirements in Contracts

### Purpose
Define cybersecurity obligations that suppliers must meet contractually.

### Business Value
Creates enforceable security expectations and reduces ambiguity during security incidents.

### DesertTech Example
Vendor contracts require encryption, access control, incident notification, confidentiality, and secure data deletion.

### Audit Evidence
- Signed contracts
- Security addendums
- Data Processing Agreements
- Contract review records

---

## 4. Supplier Risk Classification

### Purpose
Classify suppliers according to factors such as data sensitivity, business criticality, access, and dependency.

### Business Value
Allows DesertTech to spend more security resources on higher-risk suppliers.

### DesertTech Example
A vendor hosting critical production systems and confidential customer information is classified as Critical.

### Audit Evidence
- Vendor risk register
- Vendor classification criteria
- Risk scoring methodology

---

## 5. Cloud Security Responsibilities

### Purpose
Clearly understand which security responsibilities belong to the cloud provider and which belong to DesertTech.

### Business Value
Prevents security gaps caused by assuming another party is responsible.

### DesertTech Example
The cloud provider protects physical infrastructure while DesertTech manages user access, data classification, and customer-side configurations.

### Audit Evidence
- Cloud security responsibility matrix
- Cloud configuration reviews
- Access reviews
- Cloud security policies

---

## 6. Data Hosted by Third Parties

### Purpose
Understand what information third parties store, process, or access.

### Business Value
Helps protect confidential and personal information and supports compliance requirements.

### DesertTech Example
An HR SaaS provider processes employee personal information on behalf of DesertTech.

### Audit Evidence
- Data inventory
- Data flow diagrams
- Data Processing Agreements
- Vendor data classification records

---

## 7. Security Assessments

### Purpose
Evaluate whether suppliers have appropriate cybersecurity controls.

### Business Value
Identifies weaknesses that could expose DesertTech to third-party risk.

### DesertTech Example
DesertTech performs annual security assessments of Critical and High-risk suppliers.

### Audit Evidence
- Vendor security questionnaire
- SOC 2 report
- ISO 27001 certificate
- Penetration testing summary

---

## 8. Continuous Vendor Monitoring

### Purpose
Monitor supplier security throughout the relationship rather than only during onboarding.

### Business Value
Identifies changes in vendor risk and helps DesertTech respond to new threats.

### DesertTech Example
Critical vendors are reviewed annually and reassessed after major security incidents or significant service changes.

### Audit Evidence
- Vendor review records
- Updated risk assessments
- Security monitoring reports
- Certification renewals

---

## 9. Vendor Offboarding

### Purpose
Securely terminate vendor access and protect DesertTech information when a supplier relationship ends.

### Business Value
Prevents former suppliers from retaining unauthorized access or company data.

### DesertTech Example
When a SaaS contract ends, DesertTech disables vendor accounts, retrieves required data, and obtains confirmation of data deletion.

### Audit Evidence
- Offboarding checklist
- Access termination records
- Data deletion certificate
- Contract termination records

---

## 10. Evidence Required from Suppliers

### Purpose
Obtain evidence demonstrating that suppliers actually implement their stated security controls.

### Business Value
Allows DesertTech to validate supplier security instead of relying only on vendor statements.

### DesertTech Example
A Critical cloud vendor provides an ISO 27001 certificate, SOC 2 report, penetration testing summary, and BCP/DR evidence.

### Audit Evidence
- ISO 27001 certificate
- SOC 2 report
- Penetration test summary
- BCP/DR test results
- Security questionnaire
- Incident response documentation

---

## Conclusion

Third-party security is an important part of cybersecurity governance because an organization can inherit risk from its suppliers. DesertTech should use a risk-based vendor management process that covers due diligence, contractual requirements, classification, monitoring, evidence collection, and secure offboarding.
